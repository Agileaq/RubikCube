# 摄像头/图片识别魔方单面色块 — 设计文档

日期：2026-09-13
状态：已与用户对齐（A1 路线 + 3 项真机加固）

## 背景与目标

现有填色流程（Paint 页）需要用户逐格手涂 54 个贴纸。本功能让用户**拍照或上传一张单面照片**，浏览器内自动识别该面 9 个色块的颜色，经核对/修正后一键填入当前面。

约束：
- **零后端、零模型、零新依赖**：纯手写经典视觉管线（用户选定 A1 路线），完全离线可用，PWA 预缓存基本不变。
- **识别单位 = 单面**：一次识别一个面的 3×3，与现有"翻面→填色"流程对齐。
- **不直接覆盖数据**：识别结果先进核对弹窗，用户确认才写入当前面。

### 非目标（YAGNI）

- 整魔方多面一张识别（透视/遮挡难度骤增）
- 自动推断面朝向（用中心色警示 + 手动旋转替代）
- ONNX / AI 检测管线（仅预留接口，见"将来扩展"）
- 训练数据与模型

## 总体架构与数据流

```
摄像头取帧（<video> 抓帧）/ 本地图片上传
  → capture.ts    统一为 ImageData（最长边缩至 ~384px）
  → segment.ts    贴纸分割：HSV 阈值掩膜 → 3×3 中值去噪 → 连通域 → 面积/形状过滤出 9 个候选
  → geometry.ts   质心 → PCA 主轴（容忍 ~15° 倾斜）→ 符号锚定 → 投影聚类 3 行 3 列
  → classify.ts   每格中心 40% 取中值色（剔除高光）→ 白色预判 → Lab ΔE94 最近邻 → (Color, 置信度)
  → ScanResult { grid: 3×3 (Color|低置信度)[][], centerColor }
  → ScannerOverlay 核对/修正 3×3（旋转 0/90/180/270°、点格改色）
  → 确认 → useApp.setFace(face, colors[9]) 写入当前面 → 现有 solvability 校验自动生效
```

四段管线均为**纯函数**（输入 ImageData/数值，输出结果），不碰 DOM，可独立单测。

## 管线详设

### capture.ts — 图像输入统一层

- 摄像头：`getUserMedia({ video: { facingMode: 'environment' } })`；抓帧到离屏 canvas。
- 上传：`<input type="file" accept="image/*">` → `createImageBitmap(file)` → 同一 canvas 路径。
- 缩放：最长边 ≤ 384px（速度与精度的平衡点）。
- **iOS 约束（真机加固 #3）**：`<video>` 必须显式 `playsInline`、`muted`、`autoPlay`（React 属性 + 兜底 `setAttribute('playsinline','')`），否则 iOS Safari 黑屏/全屏弹窗。

### segment.ts — 贴纸分割

1. 逐像素计算 HSV；贴纸 ≈ 高饱和（彩色贴纸）或高亮度（白/黄贴纸）、局部梯度低的区域；背景（手/桌面）通常低饱和或暗。
2. 二值掩膜 → 3×3 中值滤波去噪。
3. 4-连通域标记（BFS/并查集），过滤：面积在区间内、外接框长宽比 0.6–1.6。
4. 候选 **≠ 9 时直接判定失败**（不硬猜），返回结构化错误码给 UI 引导重试。

### geometry.ts — 几何排序（核心难点）

1. 9 个候选质心 → PCA 求两个主方向向量。
2. **符号锚定（真机加固 #2）**：PCA 特征向量有 ±180° 符号不确定性，直接投影会整体颠倒/镜像。以图像坐标系（X 右、Y 下）为基准强制归一：主轴 1 取 x 分量为正的方向，主轴 2 取 y 分量为正的方向，保证展开拓扑与屏幕物理方向一致。
3. 沿两主轴投影 + 按间隙聚类切成 3 行 3 列，行内按另一轴排序。
4. 近正面拍摄不做单应变换；残余朝向误差由 UI 层旋转按钮 + 中心色警示兜底（见下）。

### classify.ts — 颜色分类

1. 每格取内圈 40% 区域像素；剔除镜面高光（V > 0.97 且 S < 0.1）后取逐通道中值。
2. **白色预判（真机加固 #1）**：S < 0.18 且 V > 0.6 直接判白——暖光下白/黄仅靠 Lab 距离易混淆，先把白色摘出，剩余 5 色再走 ΔE。阈值做成可调常量。
3. sRGB → 线性 → XYZ → Lab，与 6 色参考值算 CIE ΔE94 最近邻。**参考值直接复用 `Palette.ts` 的 6 个 hex**（模块初始化时转换一次），分类结果与 UI 色板天然一致。
4. 置信度 = 最优与次优 ΔE 之差；差值小的格子标记"低置信度"，UI 加警示边框引导重点核对。
5. 白色预判命中的格子置信度取规则阈值裕度。

## UI 流程（ScannerOverlay）

- **入口**：Paint 页按钮行新增「拍照识别」→ 打开全屏 `ScannerOverlay`（组件内弹层，非新路由，保持当前填面上文）。
- 用户先用现有翻面流程选好要填的面 → 拍照/上传识别**当前面**。
- 识别成功 → 大号 3×3 预览：
  - 旋转按钮（0/90/180/270°）调整朝向；
  - 点任意格弹出 6 色板手改（复用现有 Palette 色值）；
  - 低置信度格子加警示边框；
  - 中心色 ≠ 当前面标准色时顶部黄色警示「中心是 X，当前填的是 Y 面，确认方向？」。
- 点「确认」→ `setFace` 一次性写 9 格；「取消」无任何副作用。

## 错误处理

| 情形 | 行为 |
|---|---|
| 相机权限被拒 | 提示 + 自动切到"上传图片"模式 |
| 检出 <9 或 >9 格 | 显示抓拍原图 +「未识别到完整 3×3，请正对单面、光线均匀」+ 重试 |
| 中心色与当前面不符 | 黄色警示，允许旋转/修正后确认（不强制） |
| 个别格识别错 | 点格手改 |
| 全程 | 未确认前不触碰已填数据 |

## 测试策略

- **纯函数测试为主**：合成 ImageData 画 3×3 色格（含 ±15° 旋转、轻微透视、噪点、高光块）断言：
  - segment：恰好检出 9 域；候选异常时返回失败码；
  - geometry： PCA 符号锚定后拓扑与屏幕方向一致（构造整体旋转 180° 的用例断言不镜像）；
  - classify：白/黄暖光用例走白色预判；彩色 ΔE 匹配正确；低置信度标记触发。
- `ScannerOverlay` 组件测试仅覆盖开合/按钮（jsdom 无 getUserMedia）；识别路径由纯函数测试覆盖。
- 回归：现有 110 个测试不受影响。
